## Problem Statement
CSE graduates may have academic knowledge but may not fully match the technical, practical, and professional skills expected by the IT industry. This project converts a curriculum-industry skill-gap dataset into a simple Feast-based feature store and uses the stored features in a machine-learning workflow.

## Dataset
- **Number of skills:** 8
- **Skills:** Programming, Database, Problem Solving, Communication, Cloud Computing, Data Analysis, Teamwork, Aptitude
- **Student records:** 120
- **Target:** `Skill_Gap_Category` — Low Gap, Medium Gap, High Gap
- **Entry creation:** Synthetic student skill scores with calculated skill gaps and recommended training areas.

### Original dataset columns
`Student_ID`, `Programming`, `Database`, `Problem_Solving`, `Communication`, `Cloud_Computing`, `Data_Analysis`, `Teamwork`, `Aptitude`, individual `_Gap` columns, `Average_Skill_Score`, `Average_Skill_Gap`, `Skill_Gap_Category`, and `Recommended_Training_Area`.

## Feature Engineering
| Feature | Meaning |
|---|---|
| Programming | Programming skill score |
| Database | Database skill score |
| Problem_Solving | Problem-solving score |
| Communication | Communication score |
| Cloud_Computing | Cloud computing score |
| Data_Analysis | Data analysis score |
| Teamwork | Teamwork score |
| Aptitude | Aptitude score |
| technical_skill_score | Mean of Programming, Database, Cloud Computing and Data Analysis |
| professional_skill_score | Mean of Problem Solving, Communication, Teamwork and Aptitude |
| calculated_skill_score | Mean of all eight skill scores |

Example: `technical_skill_score = (Programming + Database + Cloud_Computing + Data_Analysis) / 4`

## Feast Architecture
```text
Original Dataset
      |
      v
Feature Engineering
      |
      v
Parquet Offline Data
      |
      v
Feast FeatureView
      |
      +-----------------------+
      |                       |
      v                       v
Historical Features      Materialization
      |                       |
      v                       v
Model Training          Online Store
                              |
                              v
                       Online Retrieval
                              |
                              v
                          Prediction
```

## Implementation
- **Entity:** `student`, using `student_id`.
- **Data Source:** local Parquet file `data/cse_skill_features.parquet` generated by the Colab notebook.
- **FeatureView:** `cse_skill_features`.
- **Feature Service:** `cse_skill_gap_service`.
- **Historical retrieval:** `get_historical_features()`.
- **Model:** Decision Tree Classifier.
- **Online retrieval:** `get_online_features()`.

## Required Analysis

### 1. What is the entity in your Feast implementation?
The entity is `student`, identified using the `student_id` join key.

### 2. List the features stored in your FeatureView.
Programming, Database, Problem Solving, Communication, Cloud Computing, Data Analysis, Teamwork, Aptitude, technical skill score, professional skill score, and calculated skill score.

### 3. Explain how one feature was calculated.
Technical skill score is the mean of Programming, Database, Cloud Computing and Data Analysis.

### 4. What is the difference between your original dataset and the feature dataset?
The original dataset contains the complete student assessment, individual skill-gap columns, target category, average gap and training recommendation. The feature dataset is a Feast-ready Parquet representation containing the entity, timestamps, eight model features and derived scores.

### 5. What is the purpose of the offline store?
It stores historical feature data and supports training and point-in-time historical feature retrieval.

### 6. What is the purpose of the online store?
It provides materialized feature values for online prediction.

### 7. What is the purpose of `feast apply`?
It registers and applies the entity, source, FeatureView and FeatureService definitions to the Feast registry.

### 8. What does materialization do?
It loads feature values from the historical/offline source into the Feast online store for online retrieval.

### 9. What is the advantage of retrieving features through Feast instead of manually calculating them separately during training and prediction?
Feast keeps feature definitions and retrieval consistent between training and prediction and reduces duplicated feature-calculation logic.

### 10. State two limitations of your current dataset.
1. The dataset is synthetic and may not fully represent real CSE graduates.
2. Industry requirements are represented by fixed benchmark assumptions and can change over time.

### 11. State two ways your feature store could be improved when more curriculum and industry evidence becomes available.
1. Add real student assessments and regularly updated industry/job-skill evidence.
2. Add internships, certifications, projects, placement outcomes and curriculum-course mappings.
